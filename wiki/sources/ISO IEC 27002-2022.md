## TL;DR

**Standard ISO/IEC 27002:2022** terza edizione (febbraio 2022), pubblicato da ISO/IEC JTC 1/SC 27. Titolo: *"Information security, cybersecurity and privacy protection — Information security controls"*. Versione 2022 sostituisce la 27002:2013 e contiene **93 controlli** organizzati in **4 themes** (Organizational, People, Physical, Technological), ciascuno con **5 attributi** che permettono filtraggi e viste multiple.

Lo standard è il **catalogo di controlli** di riferimento della famiglia ISMS: per ciascun controllo definisce **Control** (cosa è), **Purpose** (perché), **Guidance** (come), **Other information** (riferimenti). I controlli sono **direttamente mappati** sull'Annex A di [[sources/ISO IEC 27001-2022|ISO/IEC 27001:2022]] (1-a-1, stessi codici).

Per la wiki, è lo **strumento operativo per la gap analysis**: la [[sources/ENISA Mapping Table v1.0 - 2025-06-26|Mapping Table ENISA]] mappa ciascun punto del Reg. UE 2024/2690 su controlli specifici di 27002:2022. Per la transizione GRC italiana, è **lo standard più usato in pratica nel lavoro quotidiano dell'auditor / consulente** (più di 27001, che è il documento di requisiti di alto livello).

## Provenance ISO/IEC 27002:2022 vs ISO/IEC 27002:2013 — perché la verifica edizione è critica

Errore tipico in raccolte non ufficiali: file chiamati `ISO27002.pdf` che in realtà sono l'edizione **2013** (14 domini, 114 controlli, struttura completamente diversa). Per l'autore, in passato si è verificato un caso analogo (un file `ISO27001.pdf` era in realtà 27002:2005). Verifica eseguita per questo file in Wave 6 Sessione 2 — **edizione 2022 confermata**.

**Discriminanti rapidi 2022 vs 2013**:

| Indicatore | 27002:2022 (ATTUALE) | 27002:2013 (OBSOLETO) | 27002:2005 (OBSOLETO) |
|---|---|---|---|
| Numero controlli | **93** | 114 | 133 |
| Organizzazione | 4 themes (5/6/7/8) | 14 domini (5-15) | 11 domini (5-15) |
| Attributi multipli | **Sì (5 attributi)** | No | No |
| Title | *"Information security, cybersecurity and privacy protection — Information security controls"* | *"Information technology — Security techniques — Code of practice for information security controls"* | *"Information technology — Security techniques — Code of practice for information security management"* |

## Struttura — 4 themes con 93 controlli totali

### 5. Organizational controls (37 controlli)

Sotto-codice `5.1` ... `5.37`. Controlli che riguardano policy, governance, asset management, supplier relationships, incident management, compliance. **Il gruppo più numeroso**.

Esempi rilevanti:

- `5.1` Policies for information security
- `5.7` **Threat intelligence** ⭐ *nuovo controllo 2022*
- `5.23` **Information security for use of cloud services** ⭐ *nuovo controllo 2022* (rilevante per pilot Cloud NIS2 Tool)
- `5.24` Information security incident management planning and preparation
- `5.30` **ICT readiness for business continuity** ⭐ *nuovo controllo 2022*

### 6. People controls (8 controlli)

Sotto-codice `6.1` ... `6.8`. Controlli sul personale: screening, terms of employment, NDA, awareness/education/training, disciplinary process, termination, remote working, reporting events.

### 7. Physical controls (14 controlli)

Sotto-codice `7.1` ... `7.14`. Controlli fisici: perimetri, ingresso, monitoring, protezione ambientale, secure working areas, clear desk/screen, secure disposal, cablaggio.

Controllo nuovo 2022:

- `7.4` **Physical security monitoring** ⭐

### 8. Technological controls (34 controlli)

Sotto-codice `8.1` ... `8.34`. Controlli tecnologici: endpoint, privileged access, identity management, authentication, capacity, malware, vulnerability, configuration, secure development, network security, segregation, web filtering, cryptography, deletion, data masking, leakage prevention, backup, logging, monitoring, time sync, redundancy.

Controlli nuovi 2022:

- `8.9` **Configuration management** ⭐
- `8.10` **Information deletion** ⭐
- `8.11` **Data masking** ⭐
- `8.12` **Data leakage prevention** ⭐
- `8.16` **Monitoring activities** ⭐
- `8.23` **Web filtering** ⭐
- `8.28` **Secure coding** ⭐

**Totale controlli nuovi 2022: 11** (validati per pre-ingest verification — tutti rilevati nel PDF).

## I 5 attributi (§ 4.2)

Ogni controllo ha 5 attributi che permettono **viste multiple** del catalogo:

| Attributo | Valori tipici | Uso |
|---|---|---|
| **Control type** | Preventive · Detective · Corrective | Per filtrare controlli per fase del ciclo IR |
| **Information security properties** | Confidentiality · Integrity · Availability | Per filtrare per proprietà CIA |
| **Cybersecurity concepts** | Identify · Protect · Detect · Respond · Recover | Mapping a NIST CSF (NB: il CSF 2.0 ha aggiunto Govern, 27002 non riflette ancora) |
| **Operational capabilities** | Es. *Governance, Asset_management, Information_protection, Identity_and_access_management, ...* | Per filtrare per capability operativa |
| **Security domains** | Es. *Governance_and_Ecosystem, Protection, Defence, Resilience* | Per filtrare per dominio (allineato a CEN/TS 18026) |

Gli attributi sono **non normativi** — l'organizzazione può ridefinirli o aggiungere attributi propri (§ 4.2 espressamente lo consente).

## Layout di un controllo (§ 4.3)

Ogni controllo segue uno schema standard:

| Sezione | Contenuto |
|---|---|
| **Control code + title** | es. `5.7 Threat intelligence` |
| **Attribute table** | I 5 attributi del controllo |
| **Control** | Definizione one-liner del controllo (cosa è) |
| **Purpose** | Perché il controllo esiste |
| **Guidance** | Come implementare (la sezione più sostanziale) |
| **Other information** | Riferimenti incrociati, note operative |

## Cambiamenti rispetto a ISO/IEC 27002:2013 — sintesi

| Aspetto | 27002:2013 | 27002:2022 |
|---|---|---|
| Numero controlli | 114 | 93 |
| Organizzazione | 14 domini (sec. 5-15) | 4 themes (Organizational/People/Physical/Technological) |
| Title | "Code of practice for information security controls" | "Information security, cybersecurity and privacy protection — Information security controls" |
| Attributi multipli | No | Sì (5 attributi) |
| Mapping con 27001 | Annex A 27001:2013 | Annex A 27001:2022 (1-a-1) |
| Layout controllo | Variabile | Standardizzato (Control/Purpose/Guidance/Other info) |

**Riduzione di 114 → 93 controlli** è dovuta a:

- **Merging** di controlli ridondanti (es. controlli simili separati per HR onboarding e offboarding ora consolidati).
- **Riformulazione** di alcuni controlli (es. controlli di network security riorganizzati).
- **Eliminazione** di alcuni controlli obsoleti (es. controlli specifici a tecnologie superate).

E aggiunta di **11 nuovi controlli** (vedi sopra) che riflettono l'evoluzione tecnologica (cloud, threat intelligence, data leakage, etc.).

## Punti chiave per la transizione GRC italiana

1. **Standard di riferimento operativo**: nella pratica del lavoro GRC quotidiano (audit, gap analysis, scrittura di procedure), 27002:2022 è il documento **più consultato** della famiglia ISMS, più della 27001 stessa. Per l'autore: investire più tempo in 27002 che in 27001 nella fase di preparazione iniziale ISO LA è una scelta ROI-positive.

2. **5 attributi → potenti filtraggi**: l'attributo *Cybersecurity concepts* (Identify/Protect/Detect/Respond/Recover) permette di estrarre **sottoinsiemi di controlli ISO 27002 mappabili 1-a-1 su funzioni NIST CSF / FNCDP**. È uno strumento di lavoro centrale per chi opera in contesti NIS2 (linguaggio FNCDP/NIST) + ISO 27001 (linguaggio controllo).

3. **11 controlli nuovi 2022 → focus di studio**: per ISO LA prep, i 11 controlli nuovi sono **focus prioritario** perché sono materia recente (più probabile in domande d'esame) e perché riflettono trend tecnologici attuali (cloud, threat intel, DLP, web filtering, secure coding) molto rilevanti in audit reali.

4. **Threat intelligence (§ 5.7) → ponte con NIS2**: la TIG ENISA cita 27002 § 5.7 come fonte di mapping per la sezione 2 Reg. UE (Risk management policy). Per il consulente GRC che lavora con clienti NIS2 + 27001, padroneggiare § 5.7 è un *quick win* perché compare in entrambi i regimi.

5. **Information security for cloud services (§ 5.23) → ponte con pilot Cloud NIS2 Tool**: il controllo nuovo 2022 § 5.23 copre la sicurezza dei servizi cloud usati dall'organizzazione. È direttamente rilevante per i fornitori cloud italiani (soggetti del Reg. UE 2024/2690 art. 7) e per i clienti che li usano.
